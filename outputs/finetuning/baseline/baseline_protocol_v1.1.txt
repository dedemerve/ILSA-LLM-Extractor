  Source:         Researcher decision, 2026-10-06
  Rationale:      Deterministic extraction required for reproducibility of the BASE condition.
                  Non-zero temperature would introduce run-to-run variance confounding the
                  BASE vs FINETUNED comparison.

MAX_TOKENS:       8192
  Source:         Researcher decision, 2026-10-06 (increased from template default of 4096)
  Rationale:      Studies with many evidence pairs and mandatory evidence_text fields may
                  approach or exceed 4096 tokens. 8192 provides safety margin.

BASELINE_MODEL:   Mistral 7B  ← FROZEN 2026-10-06
  Source:         Researcher decision, 2026-10-06
  Decision rule:  The baseline model must use the SAME architecture as the LoRA fine-tuned
                  model so that BASE vs FINETUNED isolates the effect of fine-tuning, not
                  model-family capability differences.
  Rationale:      Both Llama-3 8B and Mistral 7B are equally unsupported by the repository.
                  Mistral 7B selected for its 32K context window, which provides appropriate
                  capacity for long source documents (45–114 KB) with system prompt, schema
                  instructions, and four few-shot demonstrations included. Reduces truncation
                  risk that the 8K Llama-3 8B window would introduce for dense papers.
  Architecture    Mistral 7B (mistralai/Mistral-7B-Instruct-v0.3 or equivalent instruct
  family:         variant). Tokenizer family: SentencePiece (Mistral). LoRA via HuggingFace
                  PEFT. The LoRA model MUST use the same Mistral 7B architecture and tokenizer
                  family. Do not substitute a different model family without documenting a
                  protocol revision.
  DO NOT USE:     Claude API, Llama-3, or any other family without explicit protocol revision.
  DO NOT run      inference until all four demonstrations are rendered and verified.

DIRECTION VOCABULARY (FROZEN)
====================================================================================================

The canonical output vocabulary for the direction field is:

  positive       — predictor is positively associated with the outcome
  negative       — predictor is negatively associated with the outcome
  mixed          — direction varies across models, countries, or outcome specifications
  not_reported   — direction cannot be established from the source text; also used when
                   the study reports a null/non-significant result without a signed effect

DO NOT output in the prompt or demonstrations:
  1          (numeric encoding — non-canonical)
  -1         (numeric encoding — non-canonical)
  0          (numeric encoding — maps to not_reported)
  "null"     (string "null" — NOT a valid direction label)
  JSON null  (JSON null is not used for the direction field; use not_reported instead)

Source: Researcher decision, 2026-10-06.
Gold records that contain direction_canonical="1" (44 rows across 4 training studies) are
NOT modified. When rendering formatted demonstrations, display direction="positive" where the
gold record has direction_canonical="1". This rendering rule was authorized by the researcher
for demonstration purposes only and does NOT rewrite any gold record.
